# 浏览器端到端测试

Playwright 测试使用独立端口 `4499`，并由 `scripts/e2e-server.js` 创建临时数据目录和本地假模型服务；不会读取或修改正式 `data/`。

当前覆盖：

- 核心循环 AI 可被真实浏览器停止，停止后迟到结果不进入草稿；
- 核心循环 AI 返回期间出现人工编辑时不覆盖人工草稿；
- 人物、关系和计划承诺在确认前只显示候选，不写入服务器；
- 候选逐项载入编辑器并手动保存后才持久化；
- 模型调用元数据按任务进入 `/api/llm-usage`，且不包含故事设想原文；
- 第一章加载故意延迟时，快速点入第二章后不会被第一章迟到响应拉回；
- 正文生成可从真实浏览器停止，假模型迟到正文不会进入编辑器或磁盘；
- 已停止的正文调用以 `chapter-generate / cancelled` 进入用量元数据；
- 浏览器真实下载作品备份，断言备份不含 API Key，再从文件选择器导入为新副本；
- 导入副本保留分部章节、人工核心循环、人物导演卡与计划承诺；
- 两个标签页基于同一正文编辑时，后保存的旧版本不会覆盖先保存的新正文；
- 冲突页刷新服务器正文时保持编辑器挂载，保留本地草稿并显示显式冲突提示；
- 带未保存冲突草稿的标签页关闭时触发浏览器 `beforeunload` 保护；
- 正文生成期间点击“书架”会先停止并核对磁盘，迟到正文不会保存；
- 正文生成期间刷新页面会触发 `beforeunload`，确认离开后上游迟到正文仍不会写盘；
- 两个标签页同时编辑章节策划卡时，旧修订保存被拒绝，磁盘保留先保存版本；
- 策划冲突页刷新最新章节后仍保留本地策划草稿，供作者核对后重试；
- 作品通过两次明确点击移入回收站，活动书架立即移除对应 ID；
- 从回收站恢复后沿用原作品 ID，并完整恢复分部和章节结构。

运行：

```bash
npm run test:e2e       # 先构建前端，再运行浏览器测试
npm run test:e2e:only  # 已有最新 web/dist 时只运行浏览器测试
```

测试基于 `playwright-core` 驱动系统 Chrome/Chromium，不下载额外浏览器；会检查 macOS 与常见 Linux 安装路径，也可通过 `PLAYWRIGHT_CHROME_PATH` 指定可执行文件。

后续应继续覆盖直接切换作品，以及账本、人物卡和删除/恢复并发冲突。
