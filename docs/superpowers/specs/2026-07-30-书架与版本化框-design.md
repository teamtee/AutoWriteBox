# 自动小说盒子 · 书架 + 统一版本化框 设计文档

> 在既有手绘风前端与三级 JSON 存储之上，新增两大能力：（1）类微信读书的书架（多书管理）；（2）把所有可编辑框统一为「可版本化字段」，每个框自带行内工具条 `上一个 · 重写 · 下一个 · 删除`，支持双向版本浏览；并将写作动作上下文化（重写/下一章只在其相关视图出现）。

- **日期**：2026-07-30
- **范围**：前端 `web/` + 后端 `server/`（数据模型、API、迁移）
- **状态**：设计已定稿，待用户复审后进入实现规划

---

## 1. 目标与边界

**目标**：
1. **书架**：一个盒子管理多本书，启动进书架，可新建/进入/重命名/删除，卡片显概览。
2. **统一版本化框**：大纲、章节正文、核心设定四子框全部统一为 `{versions, cursor}`，每框右侧行内工具条 `◀ 上一个 · 🔄 重写 · ▶ 下一个 · 🗑 删除`，双向浏览历史。
3. **动作上下文化**：解决「全书设定页也显示重写/下一章」——把动作收进各框工具条，只保留章节视图专属的「下一章 / 抽打」。

**已确认决策**：

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 版本模型 | 双向浏览：`{versions[], cursor}` 版本数组 + 当前指针 |
| 2 | 工具条粒度 | 每个框一条；核心设定四子框各自独立版本链与工具条 |
| 3 | 删除语义 | 一律只清空当前框内容（空串作为新版入历史，可用「上一个」找回）|
| 4 | 子框重写 | 核心设定子框「重写」调 LLM 重生该字段 |
| 5 | 书架操作 | 新建 + 进入 + 删除整本书（二次确认）+ 重命名 + 卡片显概览 |
| 6 | 落地路径 | 方案 A：统一「可版本化字段」抽象，前后端各一套 |

**边界**：
- 后端改数据模型（引入可版本化字段）+ 惰性迁移旧数据 + 新增统一版本端点与书架 CRUD。
- 前端新增 `VersionedBox` 通用组件与书架页；删除全局底部 `Actions` 条，动作重新归位。
- 不改企业证书/启动脚本/SSE 底层管线（复用）。

**非目标（YAGNI）**：不做跨版本 diff 对比、不做云端同步、不做封面图片上传（仅生成稳定色块）、不做多选批量删书、不做版本命名/备注。

## 2. 统一「可版本化字段」数据模型 + 迁移

### 2.1 核心结构

所有可编辑框统一为：

```json
{ "versions": ["第一版", "第二版", "…"], "cursor": 1 }
```

- `versions`：版本数组，按时间顺序，**旧版永不丢弃**。
- `cursor`：当前展示版本下标（0 起）。
- **上一个** `cursor--`、**下一个** `cursor++`，到边界时对应按钮禁用。
- **重写/生成**：新版 `push` 到末尾，`cursor` 指向末尾（保留其后旧版，不截断）。
- **删除（清空）**：空串 `""` 作为新版 `push`、cursor 指过去 → 「上一个」可找回。
- **手动保存**：变更文本作为新版 `push`（仅当 `text !== currentText`）。
- 版本上限 20（沿用现有 `HISTORY_MAX`）：超限从最旧端 `shift`，`cursor` 相应向左收敛（不小于 0）。

### 2.2 后端纯函数（`server/store.js`，可单测）

```js
function emptyVersioned() { return { versions: [''], cursor: 0 }; }
function currentText(vf) { return vf.versions[vf.cursor] ?? ''; }
function commitVersion(vf, text) {         // 新版入链、cursor 指末尾、超限裁剪
  vf.versions.push(text);
  while (vf.versions.length > HISTORY_MAX) { vf.versions.shift(); if (vf.cursor > 0) vf.cursor--; }
  vf.cursor = vf.versions.length - 1;
  return vf;
}
function moveCursor(vf, delta) {           // 边界内移动
  const next = vf.cursor + delta;
  if (next < 0 || next >= vf.versions.length) return false;
  vf.cursor = next; return true;
}
```

### 2.3 哪些框可版本化

| 框 | 现状 | 迁移后 |
|---|---|---|
| 全书大纲 | `book.outline: {content, history[]}` | `book.outline: {versions[], cursor}` |
| 章节正文 | `chapter: {content, history[]}` | `chapter.body: {versions[], cursor}`；`chapter.content` 作为**派生只读**保留（= `currentText(body)`），供 digest/prompts 读取 |
| 核心·世界观 | `settings.core.world`(string) | `settings.core.world: {versions[], cursor}` |
| 核心·文风基调 | `settings.core.style`(string) | `{versions[], cursor}` |
| 核心·禁忌约束 | `settings.core.constraints`(string) | `{versions[], cursor}` |
| 核心·篇幅节奏 | `settings.core.pacing`(string) | `{versions[], cursor}` |

### 2.4 惰性迁移

`readBook`/`readChapter` 读盘时检测旧结构并就地转换，首次写回落盘为新格式（无需独立迁移脚本，老书无缝升级、容错）：

- `{content, history[]}` → `{ versions: [...history, content], cursor: history.length }`（当前版=content 位置）。若 history 为空 → `{versions:[content||''], cursor:0}`。
- 核心字段字符串 `str` → `{ versions: [str ?? ''], cursor: 0 }`。
- 已是新结构（有 `versions` 数组）则原样返回。

纯函数 `migrateVersioned(old)` 承担转换，可单测。

### 2.5 读取点适配

- `server/prompts.js`（构造上下文读大纲/章节/核心）→ 统一走 `currentText()` 只读当前版。
- `server/llm.js` extractDigest 冒泡写 summary/progress → 不受影响（summary/progress 不做版本化，维持纯字符串）。

## 3. 后端 API

### 3.1 统一版本操作（一套覆盖所有框）

以「字段路径 `path`」定位任意可版本化框：

```
POST /api/books/:bookId/version/move    { path, delta }     # cursor±delta（±1）
POST /api/books/:bookId/version/clear   { path }            # 清空：push "" 新版
POST /api/books/:bookId/version/save    { path, text }      # 手编保存：push text 新版
POST /api/books/:bookId/version/rewrite { path }  (SSE)     # 重写：LLM 重生该框，流式
```

**`path` 白名单**（防注入，非法一律 400）：
- `outline` → 全书大纲
- `section:<sid>:chapter:<cid>` → 某章正文（sid/cid 过 `safeId`）
- `core:world | core:style | core:constraints | core:pacing` → 核心设定四子框

**`resolveVersioned(book, path)`**：把 path 解析到 `{ vf, persist }`——`vf` 是可版本化对象引用，`persist` 是落盘闭包（章节→写 chapter.json 并同步派生 `content`；大纲/核心→写 book.json）。move/clear/save 统一调用 `moveCursor`/`commitVersion` 后 `persist`。

- `move`/`clear`/`save` 返回更新后的该框 `{versions, cursor}`。
- `rewrite` 走 SSE：复用现有 `streamChat`/SSE 管线，流式产出结束后 `commitVersion(vf, fullText)` + `persist`，`done` 事件带最终 `{versions, cursor}`。
- 章节 rewrite 完成后照旧触发 digest 冒泡（读派生 `content`）。

### 3.2 rewrite 各框 LLM 指令（`server/prompts.js`）

- `outline` → 复用 `buildOutlineInstruction`。
- 章节 → 复用 `buildChapterInstruction`（rewrite 模式）。
- `core:*` → **新增** `buildCoreFieldInstruction(field, book)`：基于 premise + 其它已有设定，单独重生该字段（如「为这本书重写『世界观』，200 字内，与文风/禁忌/节奏保持一致，只输出该字段内容」）。field ∈ {world,style,constraints,pacing}，各配一句中文说明。

### 3.3 书架管理

```
GET    /api/books              # 扩展：每项带 sectionCount、chapterCount
DELETE /api/books/:bookId      # 删除整本书（递归删书目录）
PATCH  /api/books/:bookId  { title }   # 重命名
```

- `listBooks` 返回 `{ id, title, updatedAt, sectionCount, chapterCount }`（章节数=各部 chapters 累加，读 section.json 汇总）。
- `DELETE` 用 `safeId` 校验后 `rm -rf` 该书目录（`node:fs/promises` 的 `rm({recursive:true})`）。
- `PATCH` 读 book→改 title→写回（updatedAt 刷新）。

### 3.4 旧端点处置（直接删，保持干净）

移除并由 `version/*` 取代：`PUT /outline`、`PUT /core`、`PUT .../chapters/:cid`(saveChapter)、`POST .../rollback`。前端全量改造，无外部消费者。
`POST /api/gen/chapter`（下一章 next / 抽打 whip）保留——它是「新增章节内容」，与 rewrite 版本操作正交；whip/next 写入章节 body 时也走 `commitVersion`。

## 4. 前端统一 `VersionedBox` 组件 + 动作上下文化

### 4.1 `VersionedBox`（新增，通吃所有框）

```
┌─────────────────────────────────────────────┐
│ 框标题            [◀ 上一个][🔄 重写][▶ 下一个][🗑 删除] │
│ ┌─────────────────────────────────────────┐ │
│ │ 可编辑 textarea / 流式只读 + ▎光标         │ │
│ └─────────────────────────────────────────┘ │
│                                第 2 / 3 版     │
└─────────────────────────────────────────────┘
```

Props：`{ path, title, versioned, streaming, streamingText, onMove(delta), onRewrite, onClear, onSave(text) }`。

- `◀ 上一个`：`cursor<=0` 禁用 → `onMove(-1)`。
- `🔄 重写`：`onRewrite`（SSE 流式；生成中该框显示光标、工具条禁用）。
- `▶ 下一个`：`cursor>=versions.length-1` 禁用 → `onMove(+1)`。
- `🗑 删除`：二次确认（手绘确认小气泡/内联确认，不用系统 alert）→ `onClear`。
- 内容区：非流式=可编辑 `textarea`（失焦且 `text!==currentText` → `onSave`）；流式=只读 + `▎`。
- 底部「第 N / M 版」（`cursor+1 / versions.length`）。
- 复用 `.sketch`/`.hbtn`/`.cursor`，工具条按钮用 `.hbtn.mini`。

前端纯函数 `versionLabel(vf)` → `"第 N / M 版"`，`canPrev/canNext(vf)` → boolean（可单测）。

### 4.2 各视图组合

- **全书大纲**视图：一个 `VersionedBox`（path=`outline`）。
- **核心设定**视图：四个 `VersionedBox`（`core:world/style/constraints/pacing`），各自独立工具条与版本链。
- **章节**视图：一个 `VersionedBox`（path=`section:<sid>:chapter:<cid>`）承载正文 + 底部章节专属动作。

### 4.3 动作上下文化

- **删除全局底部 `Actions` 条**（当前对所有视图显示，导致大纲/核心页也出现重写/下一章）。
- 「重写 / 上一个 / 下一个 / 删除」收进各框工具条。
- 章节视图**专属**保留底部：`➡️ 下一章`（新增章节，走 `/api/gen/chapter` next）+ `🗯️ 狠狠抽打`（whip 输入，走 next 的 whip 变体，写入当前章 body 新版）。大纲/核心/书架不显示。
- 结果：大纲页只有大纲框工具条；核心页只有四子框工具条；章节页 = 正文框工具条 + 底部「下一章 / 抽打」。

## 5. 书架（Bookshelf，类微信读书）

- **启动落点**：App 启动进**书架页**；若 0 本书 → 直接进 FirstRun 开篇。
- **卡片网格**：每本书一张 `.sketch` 手绘卡片，显示书名、最后修改时间、`N 部 · M 章` 概览、按书 id 生成的稳定色块书脊（纯 CSS，无图片请求）。
- **卡片操作**：点卡片主体→进入该书；角标 `✏️ 重命名`（手绘输入，PATCH）、`🗑 删除`（二次确认，DELETE）。
- **新建**：书架首格「＋ 新建」大卡片 → FirstRun。
- **返回入口**：TopBar 书名左侧「📚 书架」返回；删除当前打开书后回书架；书架空显示引导。

前端纯函数 `bookSpineColor(id)` → 稳定 HSL（id 哈希，可单测）。

## 8. 风险与缓解

- **迁移正确性**（最高风险）：老书数据不能丢。缓解——`migrateVersioned` 纯函数充分单测（空/单版/多版/畸形）；惰性迁移只在读时转换、写回才落盘，转换失败可回退原文件（原子写）。
- **path 注入**：白名单枚举 + `safeId`，非法 400。
- **章节 content 派生一致性**：任何写 body 的路径（rewrite/save/clear/next/whip）后统一刷新 `content = currentText(body)`，集中在 persist 闭包里，避免遗漏。
