# 自动小说盒子 · UI 与交互优化 设计文档

> 在既有功能不变的前提下，重塑前端视觉（手绘草图风、双主题）与关键交互（生成状态反馈、消除 alert）。参考成熟写作类应用（Notion / Bear / iA Writer / Craft）的布局范式，把克制的手绘质感套在经过验证的布局骨架上。

- **日期**：2026-07-30
- **范围**：仅前端 `web/`，不改后端 API 与数据结构
- **状态**：设计已定稿，待用户复审后进入实现规划

---

## 1. 目标与边界

**目标**：解决两个问题 ——（1）UI 过于朴素（当前仅 15 行 CSS，浏览器默认样式）；（2）交互反馈弱（生成态不清晰、分部规划用 `alert`）。

**边界（连布局一起重构）**：
- 重写全部 CSS + 组件布局与信息层级。
- 不改后端路由、不改数据结构、不改 `store.ts`/`api.ts` 的数据契约（仅前端可新增 UI 辅助函数）。
- 交互优化聚焦：**生成反馈与状态** + **消除 alert 弹窗**。快捷键、引导教学暂不做（YAGNI）。

**已确认决策**：

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 视觉风格 | 手绘草图风（Excalidraw 风：手写体、粗描边、涂鸦阴影、不规则圆角） |
| 2 | 实现路径 | 方案 A：手写体字体 + 纯 CSS 手绘质感（不引 rough.js 等运行时库） |
| 3 | 主题 | 白纸 + 黑板双主题，右上角一键切换，localStorage 记忆 |
| 4 | 默认主题 | 白纸 |
| 5 | 字体 | 本地打包（不依赖 Google Fonts；契合企业网络/离线） |
| 6 | 交互优化 | 生成状态反馈 + 消除 alert |
| 7 | 分部规划 | 升级为可采纳面板 + 一键批量建部 |
| 8 | 改造边界 | 连布局一起重构 |

## 2. 主题系统与设计基元

### 2.1 主题机制
根元素挂 `data-theme="paper" | "blackboard"`，所有颜色走 CSS 变量。切换只改属性，无重渲染。选择存 `localStorage`（键 `novelbox-theme`），默认 `paper`。

```css
:root[data-theme="paper"] {
  --bg: #f4efe4; --panel: #fbf8f0;
  --ink: #2b2620; --ink-soft: #6b6154;
  --line: #3a332a; --accent: #c0392b; --accent-2: #2e7d68;
  --shadow: rgba(0,0,0,.15);
}
:root[data-theme="blackboard"] {
  --bg: #26302c; --panel: #2f3a35;
  --ink: #f0ebe0; --ink-soft: #b8b0a0;
  --line: #d8d0c0; --accent: #e8a24a; --accent-2: #7fc8a9;
  --shadow: rgba(0,0,0,.4);
}
```

### 2.2 手绘描边基元
```css
.sketch {
  border: 2px solid var(--line);
  border-radius: 255px 15px 225px 15px / 15px 225px 15px 255px;
  box-shadow: 2px 2px 0 var(--shadow);
}
.sketch:nth-child(even) { border-radius: 15px 225px 15px 255px / 225px 15px 255px 15px; }
```
不规则圆角是核心质感；`box-shadow` 硬阴影模拟涂鸦；偶尔 `transform: rotate(-0.4deg)` 制造随手感（克制使用，避免眼花）。

### 2.3 字体
- 中文：楷体系（`KaiTi`/`楷体` 系统兜底）；条件允许打包一款开源手写体（如霞鹜文楷/马善政楷体）到 `web/public/fonts/`。
- 英文/数字：打包 `Kalam` 或 `Comic Neue`（开源可商用）。
- 全局 `font-family` 走这套；标题字号加大、行高放松（正文 `line-height: 1.9`）。

### 2.4 留白节奏
统一内边距 16–24px，组件间距 12–16px，替换当前局促的 12px。

## 3. 三大区域视觉与布局重构

参考范式：Notion 三栏留白、Bear 稿纸阅读区、iA Writer 专注排版、Craft 卡片层级。

### 3.1 顶栏（新增）
```
┌────────────────────────────────────────────────┐
│ 📖 书名（手写大字）      [🌙 黑板] [⚙️ 设置]      │
└────────────────────────────────────────────────┘
```
- 左：书名；右：主题切换 + 设置入口（设置从侧栏底部移到此处）。
- 生成时此处显示阶段文案（见 §4.3）。

### 3.2 侧边栏
- `.sketch` 卡片包裹整体。
- "全书大纲""核心设定" → 两个置顶的醒目手绘标签按钮。
- 部：手写体标题 + 左侧竖线串起本部各章。
- 章：手绘对勾图标表示已写；当前章用 `--accent` 描边高亮（替换旧 `#eef` 淡蓝块）。
- "＋ 新建部""🧩 AI 规划分部""＋ 加章" → 小号手绘虚线按钮（dashed，暗示添加）。

### 3.3 主区（稿纸）
- 正文区做成一张稿纸卡片：`--panel` 底、`.sketch` 描边、大行高大字号。
- 标题：手写大字 + 底部手绘波浪下划线。
- "↩ 上一版"移到卡片右上角小按钮（history 非空时显示）。
- `textarea` 去默认边框融入稿纸，focus 时显手绘描边。

### 3.4 底部动作条（狱卒的鞭子）
```
┌────────────────────────────────────────────────┐
│  [🔄 重写]   [➡️ 下一章]                          │
│  ┌────────────────────────────┐  ┌──────┐        │
│  │ 狠狠抽打：写下你的不满与要求… │  │ 🗯 抽 │        │
│  └────────────────────────────┘  └──────┘        │
└────────────────────────────────────────────────┘
```
- 重写=中性墨色；下一章=`--accent-2` 草绿（推进）；抽=`--accent` 朱砂红、加大、最醒目（鞭子感）。
- 抽打输入框手绘方框，聚焦描边变色。

### 3.5 响应式
桌面优先。窄屏侧栏可折叠（汉堡按钮），窄屏保证基础可用即可。

## 4. 生成状态反馈

参考 ChatGPT/Claude 流式光标、Linear 乐观 UI、Vercel 加载骨架。

### 4.1 流式光标
生成时正文末尾跟一个闪烁手绘竖线 `▎`（CSS `@keyframes`），停止即消失。

### 4.2 全局生成态锁定（streaming=true）
- 底部动作条整体切换为醒目 `⏹ 停止`（朱砂红脉冲边框）。
- 侧栏部/章切换、加章、大纲/设定切换临时禁用（半透明 + 不可点），防止生成中切走导致状态错乱。
- 顶栏显示"✍️ 正在书写…" + 手绘小圆点跑马灯。

### 4.3 阶段感知文案
- 生成大纲 → "✍️ 正在构思全书大纲…"
- 规划分部 → "🧩 正在规划分部…"
- 下一章 → "✍️ 正在写第 N 章…"
- 抽打 → "🗯️ 正在按你的要求重写…"
- digest（后台）→ 正文出完后底部小字"📝 正在整理小结与人物…"，不阻塞。

### 4.4 完成轻反馈
生成结束：光标消失，正文卡片短暂描边高亮"落定"动画 + toast "✓ 第 N 章完成"。

### 4.5 骨架/占位
- 首次载入书树（getTree 未回）：侧栏显示手绘骨架线条，修掉"瞬时闪 FirstRun"。
- 空状态（无部/章）：主区手绘引导"点左下角 ➕ 新建第一部，或让 AI 帮你规划分部"。

## 5. Toast 系统（消除 alert）

参考 Sonner / Linear toast 范式。

### 5.1 轻量自研 toast（不引依赖）
`ToastProvider` + `useToast()` hook，右上角堆叠、手绘卡片风、自动消失（默认 3.5s，可手动 ×）。类型：
- `success`（`--accent-2` 草绿）："✓ 第 3 章完成""✓ 设定已保存"
- `error`（`--accent` 朱砂红，停留更久/需手动关）："✕ 生成失败：…"，可带"去设置"链接
- `info`（墨色）：普通提示

### 5.2 分部规划面板（升级）
- 点"🧩 AI 规划分部"→ 手绘风居中/侧滑面板（非系统 alert）。
- 面板内流式显示 AI 分部建议全文（带流式光标）。
- 底部按钮：**「✓ 采纳并创建这些部」** + **「取消」**。
- 采纳：前端解析建议文本里的分部行（匹配"第 N 部 · 标题"或"第N部"等格式），逐条调已有 `addSection` 端点批量建部；完成后 toast "✓ 已创建 N 个部"。
- 后端契约不变（复用 `POST /api/books/:id/sections`）。

### 5.3 错误提示统一走 toast
生成失败（SSE error）、保存失败、API 未配置 → 全部 toast，取代所有 `alert()`。

### 5.4 确认类
当前无危险删除操作，不做确认弹窗。

## 7. 测试策略

- **纯函数单测（vitest）**：`theme.ts`（读写/默认值）、分部建议文本解析函数（"第 N 部 · 标题" → 标题数组，含畸形输入容错）。
- **保持现有测试全绿**：`store.test.ts`、`api.test.ts` 不受影响。
- **类型检查**：`tsc -b` 零错误（注意 noUnusedLocals）。
- **构建**：`npm run build` 成功产出 dist。
- **端到端手动验收**：切主题、生成大纲（看流式光标+阶段文案）、分部面板采纳建部、抽打、回退、触发一次错误看 toast、窄屏折叠。

## 8. 非目标（YAGNI）

- 不引入 UI 框架 / CSS 框架 / 组件库（Tailwind、MUI 等）。
- 不引入 rough.js 等手绘运行时库。
- 不做快捷键、不做引导教学层。
- 不改后端、不改数据结构。
- 不做移动端专门优化（窄屏仅保证基础可用）。
- 不做删除确认弹窗（当前无危险操作）。
