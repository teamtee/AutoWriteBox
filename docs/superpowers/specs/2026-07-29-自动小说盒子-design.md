# 自动小说盒子 · 设计文档

> 一个"狱卒拿鞭子抽 LLM 写小说"的极简工具。用户只需三个动作——重写、下一章、狠狠抽打——就能驱动 LLM 完成整本小说创作。本质是对 LLM API 的一层任务化包装。

- **日期**：2026-07-29
- **形态**：本地网页应用（自用 / 小圈子），API Key 由用户自填
- **状态**：设计已定稿，待用户复审后进入实现规划

---

## 1. 目标与定位

面向**完全不懂技术的人**，把"用 LLM 写长篇小说"简化为极少数几个动作：

- LLM 负责写大纲、规划分部、写章节。
- 用户是"狱卒"，只做三件事：**不满意就重写**、**满意就下一章**、**输入一大段话狠狠抽打**（详细反馈/指令）。
- 全程不需要懂 prompt 工程、不需要手动管理上下文。

**核心价值**：把创作的复杂度（上下文管理、一致性维护、提示词拼装）全部藏进后端，前台只剩"抽鞭子"。

## 3. 整体架构

单进程后端（Express）既托管前端构建产物，又提供 API；前端是 React SPA。之所以必须有后端而非纯前端，有三个刚需：代理 LLM 调用（Key 只在后端、绕开浏览器 CORS）、读写本地文件、单端口托管前端以便一键启动。

```
自动小说盒子/
├─ 启动.command / 启动.bat     ← 双击：首次装依赖 → 启后端 → 自动开浏览器
├─ server/                     ← Node + Express 后端
│   ├─ index.js                  · 静态服务 + API 路由
│   ├─ llm.js                    · OpenAI 兼容接口封装（Base URL+Key+模型），SSE 流式
│   ├─ store.js                  · 本地文件读写（三级 JSON），history 回退栈
│   └─ prompts.js                · 大纲/分部/章节/重写/抽打/digest 的提示词模板
├─ web/                         ← React + Vite + TypeScript 前端
│   ├─ src/...                    · 侧边栏三级树、主区、三个动作、设置页
│   └─ dist/                      · 构建产物（由后端托管）
└─ data/                        ← 用户数据（本地文件，可备份/导出）
    ├─ config.json                · 全局 API 设置（唯一一份，与内容分离）
    └─ books/
        └─ <书名>/                 · 一本书 = 一个文件夹
            ├─ book.json
            ├─ section-01/
            │   ├─ section.json
            │   ├─ chapter-01.json
            │   └─ chapter-02.json
            └─ section-02/...
```

**运行时数据流**：

```
浏览器(React) ──HTTP/SSE──▶ 后端(Express) ──▶ LLM API（OpenAI 兼容）
                                 │
                                 └──▶ data/*.json（读写本地文件）
```

**一键启动脚本**：检测/安装依赖（仅首次）→ `node server/index.js` → 打开 `http://localhost:<端口>`。

## 4. 数据结构

### 4.1 全局设置 `data/config.json`（与内容分离，唯一一份）

```json
{
  "baseUrl": "https://api.deepseek.com/v1",
  "model": "deepseek-chat",
  "apiKey": "sk-xxx",
  "chapterWordTarget": 2000
}
```

- API Key / Base URL / 模型名 / 默认章节字数集中在此。
- 只由后端读写；前端设置页可修改，但 Key 不回传明文（显示 `sk-****`）。
- 换模型/换供应商只改这一处，所有书立即生效。

### 4.2 全书 `book.json`

```json
{
  "id": "book_20260729_153000",
  "title": "赛博朋克侦探故事",
  "createdAt": "2026-07-29T15:30:00Z",
  "updatedAt": "2026-07-29T16:05:00Z",
  "premise": "写一个赛博朋克风的侦探故事",

  "outline": { "content": "全书总大纲…", "history": [] },

  "settings": {
    "core": {
      "world":       "世界观/背景：时代、地域、科技或魔法体系、社会规则…",
      "style":       "文风/基调：叙事人称、语言风格、情感基调…",
      "constraints": "禁忌/约束：不能出现的内容、必须遵守的规则…",
      "pacing":      "篇幅/节奏：每章目标字数、推进快慢…"
    },
    "history": []
  },

  "characters": [
    { "name": "陈默", "role": "主角", "desc": "退役警探，冷硬寡言，为查妹妹死因入局" }
  ],

  "summary":  "全书已推进到：主角查案陷入更大阴谋…",
  "progress": "接下来第二部要揭露幕后黑手，主角与神秘女子结盟…",

  "sections": ["section-01", "section-02"]
}
```

### 4.3 部 `section.json`

```json
{
  "id": "section-01",
  "index": 1,
  "title": "第一部 · 雨夜降临",
  "outline": { "content": "本部剧情走向…", "history": [] },

  "characters": [
    { "name": "林薇", "role": "本部委托人", "desc": "神秘女子，雇主角查失踪案" }
  ],

  "summary":  "本部小结：主角接案、结识女子、发现第一具尸体…",
  "progress": "本部最新进展：写到第 3 章，主角刚锁定嫌疑人，下一章该去审讯…",

  "chapters": ["chapter-01", "chapter-02", "chapter-03"]
}
```

### 4.4 章 `chapter-XX.json`

```json
{
  "id": "chapter-03",
  "index": 3,
  "title": "审讯室的谎言",
  "content": "（正文全文）",

  "characters": [
    { "name": "老鼠", "role": "线人", "desc": "只在本章提供情报的黑市贩子" }
  ],

  "summary":  "本章小结：主角审讯嫌疑人，识破谎言，得到新线索…",
  "progress": "本章最新进展：主角拿到一张神秘地址，准备夜探仓库…",

  "status": "done",
  "history": ["旧版全文，重写/抽打前入栈，可回退"]
}
```

### 4.5 三个贯穿性机制

- **小结（summary）vs 最新进展（progress）**：summary 是"回头看"（本层讲了什么，给后文提供前情）；progress 是"往前指"（写到哪了、接下来该写什么，给后文提供路标）。每一层都有这两个字段。
- **人物按作用域分级**：主要人物放 `book.characters`，本部人物放 `section.characters`，龙套放 `chapter.characters`。写某章时按作用域拼装，不跨部污染。
- **回退栈 `history`**：正文、大纲、核心设定各自保留旧版栈，重写/抽打/手动编辑前入栈，永不丢旧内容。summary/progress/characters 为派生数据，重写时随之重算。

## 5. 界面与核心交互

### 5.1 布局

```
┌─────────────┬──────────────────────────────────────┐
│  侧边栏      │  主区（当前正在看/写的内容）           │
│             │                                      │
│ 📖 赛博朋克   │  第一部 · 第 3 章                      │
│ ▸ 全书大纲   │  《审讯室的谎言》                      │
│ ▸ 核心设定   │  ────────────────────────────        │
│ ▾ 第一部     │  （正文全文，可滚动阅读、可手动编辑）  │
│   · 第1章 ✓ │                                      │
│   · 第2章 ✓ │  ────────────────────────────        │
│   · 第3章 ●│  [🔄 重写]  [➡️ 下一章]                │
│ ▾ 第二部     │  ┌────────────────────────────┐      │
│   · 第1章 ✓ │  │ 狠狠抽打：输入你的不满/要求…  │ [抽] │
│ ⚙️ API设置   │  └────────────────────────────┘      │
└─────────────┴──────────────────────────────────────┘
```

- **侧边栏**：三级树（全书大纲 / 核心设定 → 部 → 章）。`✓`=已定稿，`●`=当前所在。点节点主区切换。
- **主区**：展示当前选中内容（章正文 / 大纲 / 设定），底部固定三个动作。正文可手动编辑并自动保存。
- 每处内容顶部有"↩ 上一版"按钮（history 非空时出现）。

### 5.2 三个核心动作（永远作用于主区当前内容）

| 动作 | 行为 |
|---|---|
| 🔄 **重写** | 当前内容入 history → LLM 用相同上下文重新生成一版 |
| ➡️ **下一章** | 自动拼装上下文生成下一章，主区跳到新章 |
| 🗯️ **狠狠抽打** | 用户输入一大段不满/要求 → 当前内容入 history → LLM 带着"训话"（最高优先级）重新生成 |

### 5.3 首次流程

空状态 → 输入一句话 → [生成大纲] → [规划分部] → 每部 [开始写第一章] → 之后进入"抽打 / 下一章"循环。

### 5.4 生成中体验

流式逐字输出（SSE），按钮转圈，可"停止"。

## 6. 后端接口

### 6.1 设置类

```
GET  /api/config          读取全局设置（Key 掩码返回）
POST /api/config          保存 Base URL / 模型 / Key / 默认字数
POST /api/config/test     连通性探针
```

### 6.2 书本/结构类（纯文件读写，不调 LLM）

```
GET  /api/books                    列出所有书
POST /api/books                    新建书（传入 premise）
GET  /api/books/:id                读取整本书的树
GET  /api/books/:id/ch/:cid        读取某章全文
PUT  /api/books/:id/...            保存内容（手动编辑，触发入 history）
POST /api/books/:id/.../rollback   回退到 history 上一版
```

### 6.3 生成类（调 LLM，SSE 流式返回）

```
POST /api/gen/outline     生成/重写全书大纲    （输入：premise + 核心设定）
POST /api/gen/sections    规划分部             （输入：大纲）
POST /api/gen/chapter     写下一章 / 重写本章   （输入：见 §7 上下文拼装）
POST /api/gen/whip        狠狠抽打当前内容      （输入：当前内容 + 用户训话）
POST /api/gen/digest      小结+最新进展+人物提取 （写完一章后自动触发）
```

所有生成类端点：旧版先入 history → 调 LLM → SSE 逐字流回 → 完成后落盘。

## 7. 提示词策略

每次生成 = **系统提示（宪法）** + **上下文（记忆）** + **任务指令**。

### 7.1 系统提示（宪法，每次都带；拼自 `book.settings.core`）

```
你是一位小说写手。严格遵守以下设定：
【世界观】{world}
【文风基调】{style}
【禁忌约束】{constraints}   ← 硬约束，最高优先级
【篇幅节奏】{pacing}
```

### 7.2 上下文（写章节时，按作用域拼装 —— 滚动摘要保证恒定轻量）

```
【全书大纲】{book.outline}
【本部大纲】{section.outline}
【本部前情】{section.summary}
【主要人物】{book.characters}
【本部人物】{section.characters}
【本章龙套】{chapter.characters}
【上一章结尾】{上一章 content 末尾若干字}
【接下来要写】{上一章 progress}   ← 路标，决定本章方向
```

不管写到第几章，喂进去的字数基本恒定（历史靠 summary 压缩），不会越写越贵/越慢。

### 7.3 任务指令（四类动作）

| 动作 | 指令核心 |
|---|---|
| 写下一章 | "根据以上，写第 N 章正文，约 {字数} 字" |
| 重写本章 | "重写第 N 章，保持大纲方向，换一种写法" |
| 狠狠抽打 | "用户对当前内容不满，要求：『{训话}』。据此重写"（训话优先级高于常规） |
| 生成 digest | "为本章输出：①简短小结 ②下一步剧情走向 ③本章新登场人物（名/身份/描述），返回 JSON" |

digest 用 JSON 返回，后端解析后分别写入 summary / progress / characters，并**向上冒泡**更新 section 与 book 的对应字段。

### 7.4 关键设计点

- **禁忌约束**置于系统提示、权重最高，最不易被违背。
- **抽打**把用户训话作为最高优先级指令插入。
- **digest 写完一章立即自动跑**，职责单一、可靠。

## 8. 错误处理

| 场景 | 处理 |
|---|---|
| API Key 缺失/错误 | 生成前校验；失败在主区顶部提示"请到 API 设置检查 Key" |
| LLM 请求超时/网络错误 | SSE 中断，保留已生成部分为草稿，提供"重试"；不覆盖旧版（旧版仍在 history） |
| LLM 返回内容为空 | 提示并允许直接重试，不落盘空内容 |
| digest 返回非合法 JSON | 后端容错解析；失败则跳过本次 digest 更新（不阻塞正文保存），可手动触发重生成 |
| 文件读写失败 | 明确报错，不静默吞掉；写操作采用"先写临时文件再原子替换"避免损坏 |
| 手动编辑冲突 | 单用户场景，最后保存为准；保存前当前版入 history |

**贯穿原则**：任何生成动作都不直接覆盖旧内容——先入 history 栈，失败可回退，符合"严禁删除后自动补全/丢内容"的要求。

## 9. 测试策略

- **后端单元测试**：`store.js`（三级文件读写、history 入栈/回退、原子写）、`prompts.js`（各动作提示词拼装正确、作用域人物拼装正确）、`llm.js`（OpenAI 兼容请求构造、SSE 解析、digest JSON 解析容错）。
- **接口测试**：各 API 端点的正常/异常路径（Key 缺失、文件不存在、回退空栈等）。
- **前端**：三级树渲染、三个动作触发正确端点、流式渲染与停止、正文编辑自动保存与回退。
- **端到端冒烟**：一句话 → 大纲 → 分部 → 写 2 章 → 抽打重写 → 回退，全链路跑通。

## 10. 非目标（YAGNI）

- 不做多用户 / 账号 / 计费。
- 不做在线部署（先本地）。
- 不做桌面 App 打包（先网页 + 一键脚本，后续再说）。
- 不做多模型对比、不做 RAG 向量检索（滚动摘要已够）。
- 核心设定暂不含"金手指/爽点"独立模块（需要时写进世界观或人物）。
