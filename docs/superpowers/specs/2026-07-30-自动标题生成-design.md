# 自动小说盒子 · 书名/部名/章名自动生成设计

> 章节正文写完后自动生成章名；每部第一章写完后自动生成部名；全书大纲生成后自动生成书名。模型只生成 10 字内纯标题，界面统一补中文序号前缀。

- **日期**：2026-07-30
- **范围**：`server/` 标题生成与迁移、`web/` 中文序号显示
- **状态**：设计已确认，待实施规划

---

## 1. 已确认规则

| 项目 | 规则 |
|---|---|
| 覆盖规则 | AI 只替换默认标题；用户手动改过的标题永久保留 |
| 书名时机 | 全书大纲生成完成后生成 |
| 部名时机 | 每部第一章正文生成完成后生成 |
| 章名时机 | 每章正文生成完成后生成 |
| 标题长度 | 模型只输出 10 字内纯标题 |
| 章节显示 | `第一章 · 夜雨来客`；无纯标题时只显示 `第一章` |
| 分部显示 | `第一部 · 暗潮初现`；无纯标题时只显示 `第一部` |
| 失败策略 | 标题失败不影响正文、大纲、摘要和 digest 保存 |

模型不得输出 `《》`、引号、`第 N 章/部`、冒号或解释。序号由界面根据 `index` 统一生成，避免模型生成错误序号。

---

## 2. 数据模型与覆盖保护

书、部、章统一增加：

```json
{
  "title": "夜雨来客",
  "titleSource": "default | ai | manual"
}
```

### 2.1 新数据

- 新建书：
  - `title` 暂时保留 premise 前 20 字，保证书架创建后有可读名称。
  - `titleSource: "default"`。
- 新建部：
  - 无显式标题：`title: ""`、`titleSource: "default"`。
  - AI 分部规划被用户采纳：保存纯标题、`titleSource: "ai"`，后续不被第一章自动覆盖。
- 新建章：
  - `title: ""`、`titleSource: "default"`。
- 用户在书架改书名：
  - 写入新标题、`titleSource: "manual"`。

只有 `titleSource === "default"` 时，自动标题任务可以写入；写入后改为 `ai`。

### 2.2 老数据惰性迁移

读盘时补齐 `titleSource`，不需要独立迁移脚本：

- 书名等于 `(premise ?? "").slice(0, 20)`：`default`；其他已有书名：`manual`。
- 部名/章名仅为默认序号（兼容 `第 1 章`、`第1章`、`第一章` 等）：清空纯标题并标为 `default`。
- 部名/章名带序号前缀和自定义内容：剥离前缀，保留纯标题并标为 `manual`。
- 其他非空标题：`manual`。
- 已有 `titleSource`：原样保留。

迁移采取保护用户数据原则：无法确认来源的非默认标题一律视为 `manual`。

## 3. 自动生成流程

### 3.1 章名与部名：复用现有 digest

现有章节正文写完后已有一次非流式 digest 请求。扩展 JSON：

```json
{
  "chapterTitle": "夜雨来客",
  "sectionTitle": "暗潮初现",
  "summary": "本章小结",
  "progress": "下一步剧情走向",
  "newCharacters": []
}
```

流程：

1. `/api/gen/chapter` 完成正文流式生成并保存 `chapter.body`。
2. 非流式 digest 根据完整正文返回章名、部名建议及既有摘要字段。
3. 若章节 `titleSource === "default"` 且 `chapterTitle` 有效：
   - 写 `chapter.title = chapterTitle`
   - 写 `chapter.titleSource = "ai"`
4. 若当前部 `titleSource === "default"`，且当前章是该部第一个成功完成正文的章节，且 `sectionTitle` 有效：
   - 写 `section.title = sectionTitle`
   - 写 `section.titleSource = "ai"`
5. digest/标题解析失败时跳过标题，正文已经保存，不向用户报整章失败。

章节重写时仍可重试生成标题，但只会更新仍为 `default` 的标题；一旦 AI 或用户已命名，不再反复变化。

### 3.2 书名：大纲完成后独立短调用

`/api/books/:id/version/rewrite` 在 `path === "outline"` 时：

1. 完成大纲流式生成并通过 `versionSet` 保存。
2. 若书 `titleSource === "default"`，调用一次 `nonStreamChat`：
   - 输入：premise + 当前完整大纲。
   - 要求：只输出 10 字内纯书名。
3. 标题有效时写 `book.title` 并标记 `ai`。
4. 标题调用失败时吞掉错误，照常发送大纲 `done` 事件。

核心设定字段重写不触发书名生成。

## 4. 标题清洗

后端新增纯函数：

```js
sanitizeGeneratedTitle(raw, unit?)
```

规则：

1. 取第一行并 `trim()`。
2. 去掉 `《》`、中英文引号。
3. 去掉开头的 `第…章`、`第…部` 及其后的 `·`、冒号、破折号。
4. 去掉模型可能输出的 `书名：`、`章名：`、`部名：`。
5. 使用 `Array.from(text).slice(0, 10).join("")` 按 Unicode 字符截断到 10 字。
6. 清洗后为空则视为失败，不写入。

所有模型输出先清洗再落盘，不信任提示词能百分百约束格式。

## 5. 中文序号显示

数据只保存纯标题和数字 `index`；前端统一格式化：

```ts
toChineseNumber(1)   // 一
toChineseNumber(12)  // 十二
toChineseNumber(101) // 一百零一

formatIndexedTitle(1, "章", "夜雨来客")
// 第一章 · 夜雨来客
```

适用位置：

- 左侧栏部标题：`第一部 · 暗潮初现`
- 左侧栏章标题：`第一章 · 夜雨来客`
- 章节正文框标题：`第一章 · 夜雨来客`
- 无纯标题时：只显示 `第一部` / `第一章`

书名不加序号，继续在 TopBar 和书架卡片直接显示。

前端新增纯函数模块 `web/src/titles.ts`，避免各组件自行拼接。

## 7. 错误处理与测试

### 7.1 错误处理

- 标题生成和标题解析均为非关键路径。
- 正文、大纲保存成功后，标题失败不得回滚正文或把 SSE 变成 error。
- 标题失败时保留默认序号；下一次正文生成/大纲重写可再次尝试。
- 手动标题永不因生成失败或重写而改变。

### 7.2 后端测试

- `sanitizeGeneratedTitle`：引号、书名号、序号前缀、多行、超过 10 字、空输入。
- 老数据迁移：默认序号识别、自定义标题保护、带前缀自定义标题剥离。
- 新建书/部/章的 `titleSource`。
- 章节生成：
  - 写入章名。
  - 第一章写入默认部名。
  - 非第一章不再改部名。
  - manual/ai 标题不被覆盖。
  - digest 失败时正文仍保存。
- 大纲生成：
  - 默认书名自动更新。
  - manual 书名不被覆盖。
  - 书名调用失败时大纲仍成功。

### 7.3 前端测试

- `toChineseNumber`：1、10、11、20、99、101、999。
- `formatIndexedTitle`：有标题和无标题两种。
- 既有前端测试、`tsc -b`、Vite 构建全部通过。

## 8. 非目标

- 不让 AI 每次重写都重新命名已有标题。
- 不生成副标题。
- 不做标题版本历史。
- 不增加新的标题编辑弹窗；本轮只复用现有书名改名，部/章标题由自动生成负责。
- 不额外增加章名/部名 LLM 请求；复用 digest。
