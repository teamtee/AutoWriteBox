## 产品定位

面向几十万到几百万字的长期网文创作，第一目标是稳定写出让读者关心人物、获得兑现并愿意继续读的正文；长期记忆、结构管理和连载工具都为这个目标服务，而不是追求“一键批量生成”。

## P0：好看度创作闭环

> 2026-08-11 确立为当前最高优先级。“好看”不由总字数、事件数量或提示词形容词代替，而以人物欲望、现场阻碍、主动行动、局势变化、代价、阶段兑现和后续牵引是否真正落到正文为准。第一阶段已把章级策划扩展为最多 12 场的有序场景链；每场记录欲望、阻碍、行动、转折和代价，完整参与备份、并发修订、生成和审稿。审稿新增“场景化与转折”，即使作者没有预填场景链，也会检查关键事件是否被概述匆忙带过。第二阶段已增加作品核心循环卡，分别固定读者期待、主角行动、阶段收益、行动代价和升级方式；它使用独立修订号并进入大纲/分部/正文生成与审稿，变化会使旧上下文结果失效，但提示词明确允许单章蓄力、变奏和余波，不要求机械重复。第三阶段已增加 AI 章节策划候选：读取全书、本部、前情、长期记忆、核心循环、所选文风资产、最近节奏记录、已有正文和作者当前表单，返回严格的章级结构与有序场景链。模型结果先进入独立候选区，作者必须先采用为编辑草稿、再手动保存；不会自动写策划卡或生成正文。生成期间正文或上下文变化会使迟到候选作废。第四阶段已增加作品级“承诺—推进—兑现账本”：严格区分作者计划与正文已向读者建立的债务，记录重要度、建立章、预计兑现窗口、有效推进、实际结果和自然产生的新承诺。生成与审稿只读取按当前全书章序实际选中的有界投影，临期和逾期债务优先；账本变化会使旧上下文结果失效。账本独立加载、随书备份，旧作品自动迁移为空账本；保存和删除都使用作品级乐观修订号，冲突时保留本地草稿并要求作者明确选择，绝不静默覆盖。

> 第五阶段已增加人物导演卡：长期记忆仍负责“正文已经发生的事实”，导演卡只负责当前欲望、恐惧、作者秘密、受压反应、说话习惯和禁用表达。关系卡记录当前温度、表面关系、私下张力、预期方向，并以“全书章序 + 新温度 + 变化原因”保存关键变化，不逐章机械打分。生成、策划候选和审稿按当前场景相关人物读取有界投影；提示词明确禁止把作者秘密当作读者或角色已知。人物卡变化会让旧生成/审稿上下文失效，独立加载、旧书迁移、备份和多页面冲突保护均已贯通。

> 第六阶段已增加“策划—成稿”差异回顾：新审稿对每个已填章级项和每个场景各返回已落地、合理改写、未落地或证据不足，证据只能来自正文；场景还要明示欲望、阻碍、行动、转折和代价的缺失或概述化。漏项可直接生成只修复该项、保留其它已完成情节的定向抽打指令。回顾同时锚定正文指纹和策划修订号；只有仍未解决的项才会投影到下一完成章之后的策划卡。作者必须逐项点击加入未保存草稿并再手动保存，系统不会把模型建议冒充故事事实。源正文或源策划变化后带入项立即失效；AI 策划候选只把它们当待作者决策的素材，等待期间变化会拒绝迟到候选。差异数据随作品备份往返保留。

> 第七阶段已增加黄金三章联合审稿：只取全书顺序的前三章，即使跨分部也不重置章序；九项检查覆盖题材与包装承诺、人物依恋、主角驱动力、核心循环、主要矛盾、差异化卖点、第一次有效兑现、三章递进和第三章后的追读力。每项结论必须引用带章号的正文证据，书名、故事设想、大纲和核心设定只能作为承诺对照，不能冒充正文兑现；整体评分明确禁止把三张单章分数相加。修复建议指向第 1/2/3 章或三章整体，可从总检卡打开对应章节，但不会自动改稿。总检锚定三章正文指纹和实际发送的作品上下文；模型等待期间任一正文或承诺变化都会拒绝迟到结果。旧结果会标为过期，并随作品备份完整往返。

> 第八阶段已增加“去 AI 味”分项修订流水线：不再用一句笼统的“写得像人”同时重写全文，而把概述化、抽象总结、重复修辞与模板句、人物同声、节奏同强度、无效段落拆成六个互斥阶段。每次只允许选择一类，提示词要求保留事件顺序与结果、人物决定、关系状态、姓名身份、数量、时间地点、能力/物品/知识边界、伏笔和章末因果，禁止顺手执行其它阶段或另造爽点反转。模型只能返回完整章节候选，不能直接写入版本链；过短摘要、代码围栏和超限结果会被拒绝。候选锚定正文指纹与实际故事上下文，等待期间发生变化即作废。页面只显示有界预览，作者采用后候选进入上方未保存正文草稿，必须通读并手动保存；保存继续沿用原有版本、摘要和审稿失效机制。

> 第九阶段已封住连续写作绕过策划的入口：末章动作不再直接调用模型生成下一章，而是先建立空章并进入策划。已保存策划必须明确目标、具体阻碍、主动选择、兑现、后续牵引，并至少包含一个具有欲望、阻碍、行动、转折和代价的完整场景，才会解锁首次正文生成；“待定、暂无、待进一步明确”等占位内容不能通过。页面逐项显示故事推进、主角行动、场景因果和有效兑现四道写前门槛。旧的服务端 `next` 调用暂时保留兼容，但正常页面流程不再使用它。

> 第十阶段已增加章节 API 上下文体检：按已发生事实、作者计划、阅读债务/导演信息和表达约束四层显示当前保存状态会装配的材料、字符/条目数、裁剪状态与缺失风险，不把正文、人物秘密或提示词原文回传界面。生成、手动审稿、自动审稿和分项重写现在都使用上一有效章；原来只有 300 字符的结尾窗口扩为最多 6000 字符，常规短章可完整承接，超长章才明确裁剪。上一章窗口、进度或人物状态变化会让旧生成/审稿结果失效；切换逐章场景文风后会刷新体检，不继续显示旧绑定。

> 第十一阶段已把“200 字世界观”升级为 API 世界圣经，并在后续质量层扩为十二栏：重构时读取故事设想、全书大纲、作品核心循环、当前草稿和其它核心设定，覆盖独特钩子、规则代价、空间层级、社会生态、势力利益、历史伤口、主角升级切口、持续看点、分阶段揭示、秘密分层与认知边界、便利设定禁区。宏大感被定义为规则从日常生活一路影响权力格局、人物机会与选择代价，并按当前圈层—中期势力/地域—长线文明/历史真相逐层可达；禁止靠名词数量和百科说明充数。世界观 API 输出前还必须内部执行“去专名可替换性、人物选择压力、分阶段剧情发动机”三项压力测试，并单列至少六类可变奏、不可机械重复的标志性场面。少于 1800 字符、漏栏、空泛薄栏或代码围栏的 API 结果不会覆盖现有版本。核心设定页显示十二栏完整度，世界观使用大编辑框；章节 API 上下文体检同步提示简略世界观风险。

> 第十二阶段正在补“场景不是卡片拼盘”的因果接口：场景链新增承接触发，第一场明确消费上一章结果或本章直接诱因，后续场必须指出上一场哪项转折或代价迫使它发生；转折必须改写人物可用资源、关系、认知、风险或下一步目标。AI 策划候选缺少任一承接触发会被拒绝，生成和审稿会用“删掉前场后后场是否仍能原样发生”检查断链。旧策划保持可用，但会收到补齐建议。

> 第十三阶段把“审稿卡只会打分”升级为 API 定向精修候选：当前有效审稿存在正文风险或未落地策划时，可把证据诊断交给正文模型；Prompt 明确保护审稿已通过的场景、既有事实、人物决定和章末因果，只修风险项，禁止用新增事故、万能能力、解释设定或提高音量伪装修复。contentRisk 留给作者核对，不允许模型擅自删改。候选同时锚定正文指纹、完整故事上下文和整份审稿内容指纹；任一变化都会作废，且候选只进入未保存正文草稿，不直接写版本链。

> 第十四阶段把“细腻、紧凑、去 AI 味”的自由文本升级为 API 文风圣经：十栏固定叙事距离、镜头选择、句段节奏、人物声音、情绪、设定展示、爽点余波、转场钩子、修辞边界，以及全书稳定锚点/场景可变范围/禁止表达。模型必须同时给出正向写法和变化空间，不能把去 AI 味写成全篇碎短句或新的模板。少于 1000 字符、漏栏、薄栏或代码围栏的 API 结果不会覆盖旧版；正文、审稿和修订稳定注入执行边界，本书文风锚点高于外部及场景资产，资产只能细化允许变化的局部维度。核心设定页和章节上下文体检同步显示文风结构风险。

> 第十五阶段已建立世界层级的证据确认闭环：分部合同只是作者计划，不会因为模型在规划中写了 `open-next` 就自动改变世界进度。手工与自动审稿只有在当前章正文确实完成本部进入门槛时，才可提交最多一条世界门槛候选；层级、相邻下一层和门槛原文必须匹配当前分部合同，证据必须逐字存在于当前正文。作者点击确认后，服务端再以正文、审稿、策划、世界圣经和世界进度版本锚写入长期状态。后续分部规划只读取这份已确认状态，已发生摘要不能自行解锁。未发布证据正文被改写或来源章删除时记录自动失效；已锁定发布版在本地改稿期间仍可作为读者已见证据，但发布新版后旧发布正文独有的门槛及其下游层级会一起退出。备份会保存记录，并拒绝活动解锁找不到来源章节或正文指纹的伪造数据。

> 第十六阶段已把“伏笔出现过”升级为可验证叙事链：章节质量合同 v3 对每笔追踪债务只允许一个节拍——植入、加压、公平误导、变义、线索碰撞或回收，并同时固定读者认知前后、人物行动后果与世界线作用。建立只能用植入，推进只能用加压/公平误导/变义/碰撞，兑现只能用回收；下一章的“读者原判断”必须精确接上上一个已确认节拍的“读者新判断”，连续第三次使用同一手法会警告机械重复。审稿 API 只能提交与 v3 策划完全一致、且逐字存在于 API 正文的证据候选；作者确认后才进长期账本。重复专名、读者判断未变或人物行动未变都不算推进。若伏笔声明“支撑下一层门槛”，还必须逐字锚定当前分部的门槛条件。证据来源改写、删章或发布新版后，该节拍及依赖它的后续 API 节拍自动失效；账本表单不能伪造、编辑或删除正文证据，内存与流式备份也会拒绝无法追溯的活动节拍。

> 第十七阶段已增加跨章场景交接快照：摘要 API 只能从本章正文最后时刻提取视角、时间地点、进行中动作、即时压力、人物/资源末态、知识边界和未完因果；`progress` 只作为摘要模型的后续建议，不能再冒充已发生事实或已确认计划。下一章正文 API 必须消费末态，跳时、转场和换视角必须写出过渡；审稿把静默重置判为风险。快照随正文变化失效，进入生成/审稿修订锚点、上下文体检与备份；旧章缺失时继续以原文窗口承接并提示重算。编辑系统不补写任何小说句子，只约束和筛选外部 API 正文。

## P1：网文创作方法库

以下规则用于规划、审稿和提示作者，不应机械套用，也不应为了指标牺牲作品本身。

### 黄金三章

- [x] 第一章：尽快给出人物处境、核心欲望或异常事件，建立阅读钩子；减少无目的背景说明。
- [x] 第二章：让冲突升级，展示题材核心机制、人物选择或世界规则，让读者明白“这本书主要看什么”。
- [x] 第三章：给出一次阶段性兑现或明确转折，同时建立后续持续阅读预期。
- [x] 三章共同完成：题材承诺、主角驱动力、主要矛盾、差异化卖点和继续阅读理由。
- [x] 审稿只指出缺失与风险，不把所有题材强行改成同一种开局。

### 单章节奏

- [x] 检查“目标 → 阻碍 → 选择 → 变化/兑现 → 新悬念”是否成立。
- [x] 每章至少产生一种有效增量：剧情、人物关系、线索、能力、世界认知或情绪变化。
- [x] 章节结尾的钩子应来自真实矛盾或信息差，避免每章都用生硬断句制造假悬念。
- [x] 连续章节检查重复桥段、重复情绪、重复解释和同质化冲突。
- [x] 控制说明、场景、对话、行动和心理活动的比例，避免长期停留在单一表达方式。

### 长篇结构

- [x] 使用“承诺（Promise）—推进（Progress）—兑现（Payoff）”检查主线和阶段目标。
- [x] 每个分部有独立目标、主要阻力、阶段高潮和状态变化，同时服务全书主线。
- [x] 给主角保留长期欲望、中期目标和当前行动三个尺度。
- [x] 重要人物通过选择、代价和关系变化塑造，不只依赖设定说明。
- [x] 爽点、压迫、反转和缓冲交替出现；记录最近章节的情绪与冲突类型，防止疲劳。
- [x] 定期检查已承诺但长期未推进的主线、人物和伏笔。

### 吸引力与可读性

- [x] 书名、简介、开篇和正文提供一致的题材承诺，避免包装与内容错位。
- [x] 尽早让主角做出有代价的选择，而不是长期被动接收信息。
- [x] 用具体场景和结果呈现设定，减少一次性百科式说明。
- [x] 保持信息差，但关键因果应可追溯，不能依赖作者临时补设定。
- [x] 审稿识别模板句、总结腔、空泛情绪、无意义填充和重复段落。

## 设计原则

- 人工确认优先：模型提取的是候选事实，未经验证不能覆盖关键记忆。
- 证据优先：所有长期记忆都能回到具体章节和正文版本。
- 分层压缩：保留完整本地事实库，按当前任务动态选取上下文。
- 发布一致：生成、审稿和长期记忆始终锚定真实发布版本。
- 技巧是启发式规则，不是批量生产模板；允许按题材、作者风格和创作阶段调整。
