## 产品定位

面向几十万到几百万字的长期网文创作，目标不是“一键批量生成”，而是帮助作者长期维护剧情一致性、控制节奏、审稿和管理连载的创作工作台。

## P0：百万字长期记忆

> 2026-08-10 基础闭环已落地：章节 digest 会提取人物、关系、能力、物品、地点、时间线、势力、伏笔、知识边界等十类“记忆候选”；候选带来源章节、正文指纹、证据与重要度，未经作者确认不会进入生成上下文。确认、忽略和冲突显式替换均有乐观并发保护；正文实际改写或来源章节删除会让旧活动事实失效，删章还会重算后续来源章序号。生成与审稿只按相关度、重要度、新近度和独立字符预算读取已确认活动事实，并明确标记预算省略。核心设定页已有中央记忆库，可筛选活动/失效/被替换事实、搜索、跳回来源章和二次确认撤销；撤销保留历史，不做硬删除。单书内存/流式备份会保留候选和事实，并拒绝无法追溯到当前正文的活动事实。章节页还可按当前正文指纹显式重算摘要、剧情路标、人物快照和记忆候选；重算只生成待确认候选，不改人工标题，期间正文变化会丢弃迟到结果。

> 2026-08-10 分层前情第二阶段已落地：完整章摘要仍在章节文件，完整本部聚合仍在分部文件；每本书另外维护由各部最近摘要派生的 2 万字符跨分部剧情窗口。写当前部时只选择它之前的分部，不会把当前部或未来部当作前情；较早内容被省略时有明确标记。正文重写、删章和 digest 事务恢复会同步重算，生成/审稿上下文修订号也覆盖实际选中的窗口，中央记忆库可直接查看。它目前是确定性“近期剧情窗口”，尚不是可人工编辑、按阶段冻结和一键全量重算的完整全书阶段总结，因此第一项仍不提前勾选。

> 2026-08-10 结构化事实阶段已落地：中央记忆库会把作者确认且仍活动的人物事实确定性聚合为人物档案，分栏展示别名、身份、阵营、性格、目标、能力、限制、当前状态和生死状态；关系事实以“主体—关系→对象”显示，能力、物品、地点、时间线、势力、伏笔和知识边界按主体形成状态台账。关系专用字段包含另一方、关系类型、强度、公开程度和变化原因；能力记录获得/升级/使用事件、代价、限制、时间与地点；物品记录持有人、来源、数量、状态和最后位置；移动记录起终点与时间；时间线记录时间、先后、持续时间、参与者和地点；势力记录成员、职位、阵营、目标、对外关系和控制区域；伏笔记录读者已知、计划/实际回收与预计截止章，并按已完成章数提醒逾期；知识边界明确作者、读者或具体人物及获知时间。专用字段随候选一起人工确认，并贯通事实库、单书备份/导入、上下文检索和前端展示；旧事实继续兼容。所有条目共享原事实的证据、来源章节和撤销入口，不复制第二份真相；单条 details 总量限制为 800 字。对同一人物生死、当前位置、物品持有人/数量、能力境界出现多个活动值的情况会只读告警，不自动覆盖。

> 2026-08-10 分层前情第三阶段已落地：作者可选择 1–20 个连续分部建立阶段摘要，使用本书 digest 模型一键重算草稿，并可编辑、冻结、解冻或删除。每条记录覆盖范围和来源指纹；来源变化后未冻结草稿会标记过期并退出生成/审稿上下文，冻结版则按作者权威选择继续使用。重算期间来源或阶段库变化会拒绝迟到结果，冻结项不允许自动覆盖；整书备份/导入保留这一层。后续上下文以阶段摘要代替已覆盖的分部摘要，未覆盖的近期分部仍按原窗口读取，不发送全文。

> 2026-08-10 发布一致性第一阶段已落地：章节页可由作者二次确认“读者已看到此版”，系统保存独立的完整正文快照、指纹、发布时间和次数，不依赖最多 20 版的编辑历史。锁定后的本地改写只形成未发布草稿，不会让读者已看到的活动事实失效；草稿候选不能确认进入长期记忆。作者明确锁定发布新版后，同章旧发布事实才退出活动上下文。快照与活动事实可一起备份/导入，导入校验同时接受当前正文或已发布指纹作为可追溯来源。该标记只记录作者已在平台完成的发布，不自动上传。

- [x] 全书剧情总结：按“章摘要 → 分部总结 → 全书阶段总结”分层维护，不依赖把全文塞进模型。
- [x] 结构化人物档案：姓名、别名、身份、阵营、性格、目标、能力、限制、当前状态、生死状态。
- [x] 人物关系图：关系双方、关系类型、强度、公开程度、变化原因、生效章节和证据来源。
- [x] 能力与境界：获得、升级、代价、限制、使用记录，防止能力凭空出现或前后冲突。
- [x] 物品与资源：持有人、来源、数量、损毁/转移状态、最后出现位置。
- [x] 地点与人物所在地：当前地点、移动事件、移动时间，检查瞬移和空间矛盾。
- [x] 全书时间线：事件时间、先后关系、持续时间、参与者、地点和来源章节。
- [x] 势力与组织：成员、职位、阵营、目标、关系和控制区域。
- [x] 伏笔管理：埋设章节、读者已知信息、计划回收点、实际回收章节、逾期提醒。
- [x] 知识边界：区分“作者知道、读者知道、某人物知道”，避免人物获取不该知道的信息。
- [x] 已发布版本锁定：长期记忆必须以读者实际看到的已发布正文为准，不能被本地重写静默改变。
- [x] 每条记忆保留来源章节、正文指纹和更新时间，可追溯、可重算，不能让模型猜测直接变成事实。
- [x] 冲突检测：新提取事实与既有事实矛盾时进入人工确认，不自动覆盖。
- [x] 上下文检索：综合当前章节、相关人物、地点、伏笔、时间、重要度和新近度选取内容。
- [x] 上下文预算：优先保留硬约束和相关事实；被省略内容必须显式标记，避免模型误以为不存在。

## P1：网文创作方法库

以下规则用于规划、审稿和提示作者，不应机械套用，也不应为了指标牺牲作品本身。

### 黄金三章

- [x] 第一章：尽快给出人物处境、核心欲望或异常事件，建立阅读钩子；减少无目的背景说明。
- [x] 第二章：让冲突升级，展示题材核心机制、人物选择或世界规则，让读者明白“这本书主要看什么”。
- [x] 第三章：给出一次阶段性兑现或明确转折，同时建立后续持续阅读预期。
- [x] 三章共同完成：题材承诺、主角驱动力、主要矛盾、差异化卖点和继续阅读理由。
- [x] 审稿只指出缺失与风险，不把所有题材强行改成同一种开局。

### 单章节奏

- [x] 检查“目标 → 阻碍 → 选择 → 变化/兑现 → 新悬念”是否成立。
- [x] 每章至少产生一种有效增量：剧情、人物关系、线索、能力、世界认知或情绪变化。
- [x] 章节结尾的钩子应来自真实矛盾或信息差，避免每章都用生硬断句制造假悬念。
- [x] 连续章节检查重复桥段、重复情绪、重复解释和同质化冲突。
- [x] 控制说明、场景、对话、行动和心理活动的比例，避免长期停留在单一表达方式。

### 长篇结构

- [x] 使用“承诺（Promise）—推进（Progress）—兑现（Payoff）”检查主线和阶段目标。
- [x] 每个分部有独立目标、主要阻力、阶段高潮和状态变化，同时服务全书主线。
- [x] 给主角保留长期欲望、中期目标和当前行动三个尺度。
- [x] 重要人物通过选择、代价和关系变化塑造，不只依赖设定说明。
- [x] 爽点、压迫、反转和缓冲交替出现；记录最近章节的情绪与冲突类型，防止疲劳。
- [x] 定期检查已承诺但长期未推进的主线、人物和伏笔。

### 吸引力与可读性

- [x] 书名、简介、开篇和正文提供一致的题材承诺，避免包装与内容错位。
- [x] 尽早让主角做出有代价的选择，而不是长期被动接收信息。
- [x] 用具体场景和结果呈现设定，减少一次性百科式说明。
- [x] 保持信息差，但关键因果应可追溯，不能依赖作者临时补设定。
- [x] 审稿识别模板句、总结腔、空泛情绪、无意义填充和重复段落。

## P1：文风与创作资产库

> 2026-08-10 已完成完整闭环：六类外部/自有来源与本书原生来源、权利和题材/场景元数据、仅链接索引、内容指纹去重、结构化文风/故事卡、主辅及逐章场景绑定、已发布正文提取原生文风、受限上下文注入、一致性审稿、删除与带绑定导出。资产上下文不携带来源作者/作品名或样本全文，绑定在生成期间变化会拒绝迟到结果。

- [x] 建立独立于单本作品的文风资产库，用户可粘贴短样本、导入自己拥有权利的正文，或登记只作索引的参考链接。
- [x] 每份资产记录名称、来源类型、作品/章节备注、权利说明、适用题材、场景标签和创建时间；不把来源不明的网络正文默认视为可复用素材。
- [x] 支持“用户原创、本人旧作、已授权、公共领域、外部短摘录、仅链接”来源分类，并在发送给模型前明确提示所选内容会进入当前 API 请求。
- [x] 将原始样本分析为结构化文风卡：叙事视角、叙事距离、句长与节奏、用词密度、对话比例、描写重心、幽默感、情绪温度、冲突频率、爽点类型、章末钩子和应避免模式。
- [x] 文风卡描述写作特征，不使用“模仿某作者”作为生成目标；外部作者姓名和作品名默认不进入正文生成提示词。
- [x] 每本书可绑定一个主文风和少量辅助资产；每章可按场景临时选择“战斗、对话、悬疑、感情、日常、高潮”等参考，避免多种风格互相冲突。
- [x] 作者确认过的本书正文可加入“本书原生文风”资产，其优先级高于外部参考，使后续章节逐渐向作品自身收敛。
- [x] 默认只发送结构化文风卡和少量必要短摘录，不把整座素材库塞进上下文；按来源权利、当前场景、相关度和字符预算决定是否携带原文。
- [x] 提供文风一致性审稿：检查句式、叙事距离、人物语言、修辞密度和节奏是否偏离所选文风，但不因合理的场景变化机械扣分。
- [x] 提供样本去重、长度上限、来源追踪、删除与导出；本地备份保留资产与书籍绑定关系。
- [x] 不自动抓取、绕过付费阅读或批量保存阅文及其它平台正文；用户需确保粘贴或导入内容具有合法来源与相应用途权限。

## P1：多 API 与多模型

> 2026-08-10 完整闭环已落地：可把当前已确认的连接保存为多个全局 API 方案，每个方案登记 1–50 个模型和用途备注，在设置页显式选择模型后快速应用。方案库和当前配置都有独立修订号与并发保护；浏览器只看到掩码 Key，改地址不会沿用旧 Key，结果不确定时会重读权威状态。当前连接和每个方案都可通过受限的 `GET /models` 检查并发现模型：不发送正文、不跟随跳转，限制 30 秒和 1 MiB 响应，同步时保留显式选中模型。「模型分工」可把正文、大纲/设定、摘要/记忆、审稿、书名/章名分别绑定到任意方案模型；未绑定的任务使用当前默认连接。每本书还可在核心设定页固定一个方案模型，优先覆盖该书所有模型任务；一次生成开始时会锁定所选模型，期间修改绑定只影响下一次任务。绑定保存在全局方案库，单书导出不携带绑定或 Key。删除方案或移除已绑定模型会安全清除对应分工与单书绑定；任何已选模型失败都不会静默切换。

- [x] 支持多个 API 服务配置及快速切换。
- [x] 一个服务配置可维护多个模型。
- [x] 正文、大纲、摘要、审稿、标题可分别选择模型。
- [x] 支持全局默认模型和单书固定模型。
- [x] 提供连接测试、模型列表、用途备注和安全的 API Key 管理。
- [x] 模型失败时不默认静默切换，避免文风、成本和上下文能力突然变化。

## P2：连载与平台发布

> 2026-08-10 发布辅助闭环已落地：书架可导出只含书名、部名、章名与正文的 UTF-8 TXT，空章会跳过并提示；章节页可按当前正文指纹运行发布前检查，确定性检查章名/控制字符/异常空行/正文首行重复章名，并用整书指纹筛选后逐字复核完全重复章节。剧情增量、章末钩子、长线/文风/包装一致性和内容风险线索只读取当前有效审稿，缺少或过期时明确标为待检查。连载管理页提供有正文未发布/发布后修改的存稿箱、当前发布状态、按最近一次锁定快照汇总的更新日历、今日发布字数进度和随作品备份的每日目标；大型作品只读取章节有界投影，不向作品树回传正文。平台人工核对记录保存官方规则、AI 政策、合同说明、核对时间和官方接口证据，30 天后提醒复查；发布前检查即使找到近期记录仍固定为人工确认，不会冒充已合规。同步策略固定为 `manual-only`，当前没有登录、验证码或自动上传能力；只有近期且明确授权发布的官方 API 证据可成为未来集成候选，仍不会自动启用。发布锁和 TXT 均不自动上传平台。

- [x] 存稿箱、更新日历、每日字数目标和已发布状态。
- [x] 发布前检查：章节格式、重复内容、剧情增量、结尾钩子、一致性和潜在合规风险。
- [x] 先提供适合复制到作者后台的纯文本导出。
- [x] 提供可追溯的平台规则、AI 内容政策和合同人工确认记录；发布前仍由作者打开最新官方信息复核，工具永不判定“已合规”。
- [x] 建立官方接口同步能力门禁：当前固定仅手动发布；只有平台提供且明确允许发布的官方 API 才能成为未来候选，登录自动化、验证码绕过和平台限制绕过永久禁止。

### 持续发布约束（不是一次性完成项）

- 每次实际发布前，作者都要重新确认记录中的官方页面和本人当前适用合同仍未变化；30 天仅为工具提醒周期，不是安全期或合规保证。
- 任何未来平台同步开发都必须重新验证官方 API 的提供方、授权范围和当前有效规则；证据缺失、过期或需要模拟登录/处理验证码时保持手动发布。

## 设计原则

- 人工确认优先：模型提取的是候选事实，未经验证不能覆盖关键记忆。
- 证据优先：所有长期记忆都能回到具体章节和正文版本。
- 分层压缩：保留完整本地事实库，按当前任务动态选取上下文。
- 发布一致：生成、审稿和长期记忆始终锚定真实发布版本。
- 技巧是启发式规则，不是批量生产模板；允许按题材、作者风格和创作阶段调整。
