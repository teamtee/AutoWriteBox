# 好看正文：Prompt 与上下文组织

本文定义自动小说盒子的正文生产职责：正文由用户配置的模型 API 生成；产品负责组织必要上下文、约束生成、审查成稿，并让同一 API 或指定审稿模型定向返修。编辑侧不直接代写正文。

## 一、生成闭环

1. 从正式书库与作者资产读取事实、计划、记忆和表达约束。
2. 先生成章节策划候选，人工采用并保存后才成为当前章意图。
3. 正文模型只收到当前任务需要的上下文，不接收整座素材库或百万字全文。
4. 成稿先经过确定性检查，再由审稿模型按固定检查表提供正文证据。
5. 未达门槛时，只携带原稿、未通过项、保留项和定向返修指令请求 API 重写。
6. 候选与正式版本分离；作者确认后才保存、提取摘要和生成长期记忆候选。

## 二、上下文分层

### A. 已发生事实层

包括读者已看到的发布快照、前情摘要、已确认长期记忆、人物与物品当前状态、上一章结尾。它们是连续性硬约束。模型不能为了爽点改写伤亡、数量、时间、位置、能力限制或人物已经知道的信息。

### B. 作者计划层

包括全书大纲、本部大纲、章节策划和仍在“计划中”的承诺。它们描述方向，不是已经发生的事实。模型必须通过人物行动和具体场景把它们变成正文，不能让旁白直接宣布计划已完成。

### C. 阅读债务与秘密层

包括已建立待兑现的承诺、伏笔回收窗口、人物私下秘密和作者导演卡。作者知道不等于读者或人物知道。秘密只驱动选择、回避与潜台词，必须经过正文中的获知过程才能公开。

### D. 表达层

包括文风资产、叙事距离、句式节奏、对话差异与去 AI 味规则。表达层只决定怎么写，不能覆盖事实、动机和因果。

冲突优先级固定为：禁忌硬约束 → 已发生事实 → 当前章明确策划 → 长线大纲 → 表达偏好。信息不足时保留未知，禁止临时补万能设定。

## 三、动态选择，而非全文灌入

每次请求按任务选择材料。单个字段的字符上限只表示该层最多想发送多少，不能各自占满后再相加；
服务端先按“禁忌与硬约束 → 本章策划 → 上一章连续性 → 当前稿 → 长期记忆 → 前情与大纲 → 表达资产”分配单次总预算。
内容为空的层不占额度，被裁剪的层必须列出需求、实发和保底，并明确告诉模型“未发送不等于不存在”。
章节页的 API 上下文体检显示同一份分配结果。全局默认连接和 API 方案中的每个模型可以分别登记上下文窗口；任务模型分工或单书固定模型生效时，生成、审稿与体检都使用被选中模型的窗口，不用当前默认模型冒充。当前部摘要预算为 2 万字符，跨部前情合计为 6 万字符；
单部不再只切尾窗，而是保留开场、与本章点名实体相关的旧条目和收尾。

- 章节策划读取全书方向、本部前情、上一章路标、相关人物、到期承诺和近期节奏记录。
- 正文生成再加入已保存章节策划、相关长期事实、上一章结尾、绑定文风卡和人物导演卡。
- 审稿读取与生成相同的事实锚点，并加入当前完整正文；策划文字不能充当正文证据。
- 定向重写只加入原稿、具体失败项、必须保留项和连续性上下文，不重新开放自由创作范围。

新版审稿还会从正文实际表现中提取五维受控节奏指纹：压力轨迹、破局方式、兑现规模、章末钩子机制和关键代价。系统只对这些枚举做确定性比较：连续三章同一维度、连续两章完整同构，或最近五个有效记录中四次由同一手法支配，会作为可解释风险进入下一章策划、正文和审稿 Prompt。它不是“轮换表”；若人物因果要求延续同类手法，应让后果、规模或代价发生读者可感知的升级，而不是仅替换名词。

新章节策划在写正文前还要明确同样五维的“节奏意图”。策划 API 必须从受控枚举选择，并先与最近有效指纹比较；当前网页启用意图 v1 后五项缺一不可。旧策划、旧客户端和旧备份继续按 v0 兼容，只提示升级。正文 API 执行意图但不把后台标签写进小说；审稿 API 再独立从正文提取实际指纹，并把完全落地、合理因果改写或无效偏离写入策划—成稿差异。节奏差异只诊断当前章，不能作为下章必须继承的未决剧情。

人物、地点、物品、伏笔和知识边界按“本次任务直接相关 → 近期上下文相关 → 重要度 → 新近度”与字符预算检索。任务直接相关事实先独立装填；长事实宁可裁剪说明字段也不能整条丢弃后用无关短事实填满。主体和别名至少两个字符才参与精确子串命中，避免单字主体污染召回。本次任务直接相关不是泛指当前章节，而是由已保存/临时章节策划的目标、阻碍、选择、兑现、钩子、张力、埋点、世界展开、备注与逐场因果，以及待审/待重写正文中实际点名的主体、对象和结构化细节触发；因此久未登场的旧人物、物品、地点或伏笔不会只因近期摘要没提到就被挤出。被预算省略的内容要明确标记，不能让模型误以为不存在。digest 提取的最高重要度候选只有在主体和值都能从当前正文精确定位时才自动进入事实库，并标记为“自动采纳”；作者可事后否决。低重要度、抽象概括、正文无法精确定位或与活动事实冲突的候选继续等待人工确认。

章节页提供“API 上下文体检”：按事实、计划、阅读债务和表达四层显示当前已保存状态会为 API 装配哪些材料、字符或条目数量、是否裁剪，以及缺少上一章、张力、埋点、世界边界、文风锚点、阅读债务、节奏历史或人物声音时的风险。长期记忆项额外显示活动事实数、本次任务直接命中数、实际装入数和预算省略数；若连本章直接点名的事实也无法全部装入，则作为生成风险提示作者精简同名冗余或拆分任务。体检不返回正文、秘密或提示词原文。上一有效章最多携带末尾 6000 字符；常规短章因此可以完整承接，超长章会明确标出裁剪。审稿和定向重写也读取同一上一章窗口，窗口变化会使等待中的旧结果失效。

摘要 API 还会从当前章正文最后时刻提取“场景交接快照”：视角、时间、地点、进行中动作、即时压力、人物末态、资源末态、读者/人物知识边界和仍在生效的未完因果。它只能依据正文结尾，不能读取 `progress`、未来策划或预测补写；正文原文和作者确认事实始终高于快照。`progress` 被明确降级为摘要模型给出的后续走向建议，不再冒充“接下来必须写”的事实。下一章正文 API 必须先消费交接末态；若要跳时、转场或换视角，必须写出读者可感知的过渡和因果。审稿 API 会把静默重置判为风险。快照随正文修改失效、随备份迁移，并参与生成与审稿修订锚点；旧章缺失时继续使用原文窗口，同时提示显式重算。

## 四、章节策划的八个核心对象

### 1. 目标

谁在本章想完成什么，必须能够被读者感知。

### 2. 阻碍

现场中什么具体力量阻止目标，以及压力为什么会变化。

### 3. 选择

人物主动做什么、放弃什么、承担什么。关键答案不能连续由向导递交。

### 4. 兑现

本章对铺垫或蓄力给出什么信息、关系、能力、资源或情绪回报。兑现必须由行动和代价挣得。

### 5. 钩子

由本章结果自然产生的未完成行动、真实矛盾或信息差，不用生硬断句假装悬念。

### 6. 张力曲线

写清压力如何随人物行动至少两次变化：何处出现希望、小胜或暂缓，何处被误判、反制或新代价打破，关键选择后如何兑现并留下余波。它不是固定五段式；安静章也可用关系距离、信息可信度和选择成本形成起伏。

### 7. 分层埋点

根据本章功能选择回收、推进或建立，不要求每章三者全做。每条线索都写清具体载体、当下用途、人物反应和信息边界。线索要作为物件、动作、矛盾或错误判断参与当前场景；只抛神秘名词、旁白预告意义或延后解释，不算埋点。

被长期账本追踪的埋点使用 v3 叙事链。每章只选一拍：植入、加压、公平误导、变义、线索碰撞或回收。建立承诺只能植入，推进债务只能加压/公平误导/变义/碰撞，兑现债务只能回收。策划还必须写清“读者原判断 → 本章后新判断”、引发的人物行动/风险变化，以及它是否深化当前世界层或支撑下一层门槛。下一拍的读者原判断必须接上上一拍已确认的新判断；连续第三次用同一手法会触发机械重复警告。

公平误导可以让角色和读者得出暂时错误的解释，但不能隐藏视角人物已经看见的关键事实。“同一个名词又出现了”不是推进；至少要让读者判断或人物行动发生可证明的变化。审稿 API 只能提交正文连续原句作为落地证据；系统校验动作、节拍、认知变化、行动后果和世界线作用与策划完全一致后，仍需作者点击确认才写入账本。

没有到期阅读债务且本章应专注行动、关系或阶段兑现时，允许选择“无埋点任务”，但必须明确三个对象：为什么本章不处理或建立债务、本章把注意力用于什么、哪些既有未知保持原状态。这不是逃避长线：进入兑现窗口或逾期的债务必须推进、兑现，或用稳定后台 ID 写清有因果的延期原因与下一检查点。任务合同与无任务合同不能同时成立。

### 8. 世界边界扩张

每章最多打开一个主要新层级，通过人物能触碰或验证的地域、制度、历史痕迹、力量差或异常结果让世界变大，同时明确仍未知什么。宏大感来自旧认知边界被证据推开，不来自百科段落、专有名词数量、突兀全知镜头或反派自报设定。

场景链继续使用“人物欲望 → 现场阻碍 → 具体行动 → 局势转折 → 代价/后果”。后一场必须由前一场的新局势触发。

## 五、去 AI 味不是一句提示词

系统不使用“写得像人”作为唯一要求，而是检查可定位特征：

- 成片十二字内独立短段和同段长节奏；
- 密集排比、“不是……而是……”和同构转折句；
- 替读者总结主题或替人物宣布情绪；
- 人物说话同声同气，只有信息功能；
- 抽象感叹、比喻堆叠和重复意象；
- 用说明或修辞掩盖人物没有行动、场景没有转折。

审稿必须指出正文位置或短小局部特征。返修时删除总结腔、恢复人物即时目的、打散同构节奏，但保留真正符合人物与场景的少量有力表达，不能把文字压成干瘪提纲。

## 六、审稿门槛

每次章节审稿独立检查：开场、人物主动性、场景因果、有效增量、兑现、章末钩子、张力起伏、埋点落地、世界边界展开、自然人感、表达比例、重复风险、长线推进、文风与包装一致性、内容风险。

重复风险必须结合最近有效节奏指纹。当前章若继续复刻系统已经标出的完整签名或连续维度，却没有新的因果升级，应给出正文证据并判为风险；上下文没有记录时不得猜测历史，合理延续也不得因机械求变被扣分。

每一项都必须返回 `pass`、`risk` 或 `na` 和正文证据。以下情况必须定向返修：

- 开场静默重置上一章的视角、时间地点、进行中动作、伤势、关系、资源或知识边界；
- 策划中的目标、关键选择、张力转折或兑现只存在于策划卡；
- 伏笔没有载体、当下作用或人物反应；
- 世界观只靠讲解、全知切镜或名词堆叠；
- 章节从头到尾同一压力，或只靠连续事故升高音量；
- 审稿判定存在具体模型腔，却只给“加强描写”一类空建议。

返修指令必须包含：问题位置、正文证据、要保留的有效部分、具体改法和不能改变的事实。重写结果仍是候选，不能自动覆盖作者确认版本。

所有小说正文必须由项目配置的 API 模型生成。编辑系统只负责装配上下文、生成任务书、验证策划、调用 API、证据审稿和发起定向返修。API 正文、重写、抽打及精修候选在落盘前统一经过后台信息泄漏检查；债务 ID、策划动作锚点、成组合同标签或审稿 JSON 字段一旦混入正文，本次结果直接拒绝，已有正文保持不变。

审稿 API 也不能直接“宣布伏笔已推进”。它只能引用策划卡中的稳定债务 ID，并提交“动作 + 叙事节拍 + 读者认知变化 + 行动后果 + 世界线作用 + 账本摘要 + 正文连续原文证据”候选；候选要通过服务端对 v3 策划、账本状态、上一节拍与正文原文的确定性校验，最后由作者确认才更新长期账本。证据来源改写、删章或发布新版后，该节拍和依赖它的后续 API 节拍会自动退出活动上下文。

宏大世界采用三层揭示路线：当前生活圈、中期势力与地域、长线文明与历史。每层都必须有阅读承诺、可验证证据、人物行动、选择代价、认知增量、保留未知和进入下一层门槛；章数只作节奏参考，上一层门槛没有被已发生正文证明时，API 不得越级调用下一层答案。

## 七、《笼中火种》第 21 章验证协议

第 21 章使用 `scripts/api-editorial-loop.js` 运行真实“API 生成 → API 审稿 → API 定向重写”闭环。脚本分别读取项目中的正文和审稿任务模型分工，而不是直接硬读默认连接；初稿与返修使用正文模型，证据审稿使用审稿模型。任务策划缺少张力曲线、分层埋点或世界边界扩张时会在外发前拒绝执行。

每轮正文和审稿都单独留档。下一轮不从“最新轮”机械继续，而从当前通过确定性门禁、审稿风险项最少的 API 候选继续定向修改。最终 manifest 记录 `selectedIteration` 和 `selectedStatus`；未达到分数及证据门槛时只标记待作者审阅，不会把最后一版自动视为成稿。

真实调用会把任务书列出的作品材料发送给当前配置的外部模型服务，因此必须得到用户明确授权并显式传入 `--ack-send`。未授权时只运行 `--dry-run`，检查模型、文件清单、上下文长度和输出位置，不发送内容。

## 八、世界观不是 200 字背景简介

“世界很大、势力很多、主角将逐步探索”不能为正文提供可执行因果。世界观改为由配置 API 生成的十二栏世界圣经：一句话钩子、独特机制、底层规则与代价、空间层级、社会生态、势力利益、历史伤口、主角切口与升级路径、持续看点与标志性场面、分阶段揭示路线、秘密分层与认知边界、便利设定禁区与保留未知。

生成时同时读取书名、故事设想、全书大纲、作品核心循环、当前世界观草稿和其它核心设定；世界观草稿作为待改进材料放在用户指令中，不再作为系统级既定规则反向约束自己的重构。结果少于 1800 字符、缺任一栏目、除一句话钩子外任一栏少于 50 字符，或含代码围栏时，API 输出不会落入版本链。

世界圣经必须至少建立三条相互咬合的因果链：规则如何改变普通人的日常与生计；如何塑造权力、阶层和势力利益；如何给主角机会并收取代价。宏大展开按“当前生活圈 → 中期势力/地域 → 长线文明或历史真相”逐层抵达，每层先用可验证证据兑现旧问题，再打开更大的问题。它是作者后台全貌，不等于读者或角色已经知道；章节策划质量合同 v2 必须先声明“展开前认知”，再让人物通过行动中的证据推进一个边界增量，并由新认知改变选择或代价。已经揭示的规则直接用于行动，不得重复包装成新谜底；尚未揭示的真相只能留下符合当前视角的结果、矛盾或痕迹。

为了阻止 API 用一段漂亮空话伪装“可持续”，世界圣经还有两组子合同。“持续看点与标志性场面”必须覆盖日常生计、规则博弈、关系交换、势力冲突、探索发现、阶段兑现六类，并为每类写清看点、行动、阻碍、代价和变奏边界；“秘密分层与认知边界”必须区分作者底层真相、当前读者已知、当前主角已知、关键势力认知差、下一阶段可验证和保留未知。缺少子标记、顺序错乱或内容过薄，同样不会保存 API 结果。

这条路线现在还会进入分部规划 API。每一部都必须把“这一层向读者承诺什么”转化成本部内的可核验证据、人物主动行动、选择代价和认知增量，同时声明仍保留的未知。进入下一层不是章号或地图标签，而是一个必须在正文中由行动与证据完成的门槛。方案可以用多个分部深挖同一层，但不得倒退、跳层或“本部未开门，下部忽然出现更大势力”。采纳后整组世界推进合同被写入本部大纲，成为章节策划与正文 API 的实际上下文，而不是只在设定页里显得宏大。

章级不只收到整段本部大纲，还会收到从其中提纯的高优先级世界合同。因此章节策划不能从作者后台的长线真相中任选一个“大设定”当爆点；它只能在本部当前层级内，用本部允许的证据和认知增量组织人物行动。手工审稿、自动审稿和 API 精修也共用它，专门检查三类越权：提前泄露保留未知，超出当前层级，以及未用正文证据完成门槛却声称已进入下一层。合同标签是编辑后台语言，出现在 API 正文或精修候选中会被确定性拒绝。

`open-next` 现在只表示“本部计划完成这个门槛”，不表示系统已经解锁。审稿 API 只能用本章正文中的连续原句提出门槛候选；候选层级、相邻下一层和门槛文字都必须与当前本部合同一致。只有作者点击确认，长期世界进度才改变。后续分部规划以这份确认状态为唯一解锁依据，不能根据章数、摘要或模型推测跳层。未发布正文删掉证据后确认记录会失效；若该指纹已经被作者锁定为发布版，则继续视为读者已见事实。
